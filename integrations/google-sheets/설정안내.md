# 이름·휴대폰 번호 → 구글 시트 연결

사이트 코드는 준비되어 있습니다. 아래 Google 설정과 환경변수를 적용해야 실제 저장됩니다.

## 1. Apps Script 코드 붙여넣기

1. [출시알림신청자DB](https://docs.google.com/spreadsheets/d/16uW5SoSuHZsWsrlsE5alwIbRjoJyiWgulyZ1asOfRco/edit)에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 이 폴더의 `Code.gs` 파일을 VS Code로 열어 전체 내용을 복사합니다.
3. Google 편집기의 기본 `myFunction` 코드를 지우고 복사한 코드 전체를 붙여넣습니다. 기존에 사용 중인 스크립트가 있다면 덮어쓰지 말고 별도 스크립트 프로젝트를 사용하세요.
4. 저장합니다. 시트 ID는 이미 입력되어 있습니다. `doPost`의 **실행** 버튼은 누르지 않습니다. 이 함수는 사이트에서 제출할 때 실행됩니다.

## 2. 비밀키 설정

Apps Script 왼쪽 **프로젝트 설정(톱니바퀴) → 스크립트 속성 → 스크립트 속성 추가**에서 아래 값을 저장합니다.

| 속성 | 값 |
| --- | --- |
| `WEBHOOK_SECRET` | 직접 생성한 32자 이상의 무작위 문자열 |

같은 비밀키를 아래 사이트 환경변수에도 사용합니다. 비밀키는 채팅이나 공개 코드에 올리지 마세요. 프로젝트 폴더의 터미널에서 아래 명령으로 생성할 수 있습니다.

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

## 3. 웹 앱 배포

오른쪽 위 **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**을 선택합니다.

- 설명: `동백 출시 알림 접수`
- 실행 사용자: **나**
- 액세스 권한: **모든 사용자 / Anyone** (로그인이 필요한 옵션은 선택하지 않습니다.)

**배포**를 누르고 본인 Google 계정으로 권한을 승인합니다. 배포가 끝나면 `/exec`로 끝나는 **웹 앱 URL**을 복사합니다. 이 웹 앱은 비밀키가 일치하는 저장 요청만 받으며 시트 내용을 읽어주는 기능은 없습니다. 시트 자체의 공유 권한을 공개로 바꿀 필요는 없습니다.

조직 계정에서 ‘모든 사용자’ 옵션이 없으면 조직의 Apps Script 웹 앱 정책을 확인해야 합니다.

## 4. 사이트에 환경변수 추가

프로젝트 루트의 `.env.local` 파일에 다음 두 줄을 추가합니다. 기존 Supabase 설정은 유지합니다. `env.example` 파일도 참고할 수 있습니다.

```dotenv
GOOGLE_SHEETS_WEBHOOK_URL=여기에_복사한_웹_앱_URL
GOOGLE_SHEETS_WEBHOOK_SECRET=위에서_설정한_비밀키와_똑같은_값
```

환경변수 이름에 `NEXT_PUBLIC_`을 붙이지 않습니다.

- 로컬: 실행 중인 개발 서버를 종료한 후 `npm run dev`로 다시 실행합니다.
- 배포 사이트: 호스팅 서비스의 환경변수에도 두 값을 추가하고, 이번 코드 변경과 함께 다시 배포합니다.

## 5. 확인

1. 사이트의 출시 알림 신청에서 이름과 본인의 테스트용 휴대폰 번호를 입력하고 수집·이용 동의 후 제출합니다.
2. 완료 문구가 표시되는지 확인합니다.
3. 구글 시트에 **출시알림접수** 탭이 생성되고 접수시각(KST), 이름, 휴대폰번호, 동의 여부, 동의문 버전, 신청경로가 저장되는지 확인합니다. 기존 `시트1`은 유지됩니다.
4. 같은 번호로 다시 신청하면 기존 행을 유지하며 추가 행은 만들지 않습니다. 휴대폰 번호 맨 앞의 `0`도 유지됩니다.
5. 동의하지 않거나 번호 형식이 잘못된 경우 저장되지 않는지 확인합니다.

이름과 휴대폰 번호를 **저장하는 연결**입니다. 문자/카카오 알림 발송은 별도 서비스 연결이 필요합니다. 폼에 표시한 보유 기간에 따라 발송 완료나 동의 철회 시 운영자가 시트의 해당 정보를 삭제해야 하며, 자동 삭제 기능은 포함하지 않습니다. 실제 운영 정책에 맞게 동의 문구를 변경할 경우 사이트와 Apps Script 양쪽의 동의문 버전도 함께 변경하세요.

## 문제가 생겼을 때

- ‘접수를 준비 중’ 문구: 환경변수 두 개, 비밀키 길이(32자 이상), 개발 서버 재시작/재배포를 확인합니다.
- ‘접수 결과를 확인하지 못했습니다’ 문구: Apps Script의 비밀키가 같은지, 웹 앱 권한이 ‘모든 사용자’인지, URL이 `/exec`로 끝나는지 확인합니다. Apps Script의 **실행 내역**에서 호출 여부도 확인할 수 있습니다.
- 기존에 `출시알림접수`라는 탭이 있고 열 제목이 다르면 저장을 중단합니다. 다른 탭 이름을 `Code.gs`의 `TAB_NAME`에 지정하고 새 버전을 배포하세요.
- Apps Script 코드를 바꾸면 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**를 눌러 반영합니다. 같은 배포를 수정하면 기존 웹 앱 URL을 계속 사용할 수 있습니다.
- 웹 앱 URL을 브라우저 주소창에서 여는 것만으로는 접수가 되지 않습니다. 사이트의 제출 버튼으로 확인하세요.

공식 안내: [Apps Script 웹 앱 배포](https://developers.google.com/apps-script/guides/web).
